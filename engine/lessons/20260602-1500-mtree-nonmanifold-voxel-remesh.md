# Reducing MTree (Modular Tree) meshes to low-poly: Decimate & Quadriflow refuse, Voxel remesh works

## Symptom
A tree generated by the **MTree / "modular_tree" Blender addon** comes in extremely dense
(observed: 154,168 tris trunk+branches, plus a Geometry Nodes leaf scatter at 350 density ×
594-tri leaf source = **14.7 MILLION** evaluated tris). Attempts to slim it fail mysteriously:

- **Decimate (Collapse)** floors and basically refuses to reduce. Setting `ratio = 0.05`
  (5%) still returned `face_count = 12244` on a ~12.5k mesh - the ratio is ignored.
- **Quadriflow remesh** aborts with: *"the mesh needs to be manifold and have face normals
  that point in a consistent direction"* - output identical to input.

## Root cause
MTree output is **non-manifold** (branches are grafted onto the trunk surface as separate
tubes with T-junctions / inconsistent normals; canopy is thousands of twig stubs). Both
Decimate-Collapse and Quadriflow require clean manifold topology to operate, so they silently
floor or refuse. `remove_doubles` welds it into one connected component but does NOT make it
manifold, so Collapse still refuses.

Also note: there is **no MTree node tree left in the .blend** once the mesh is generated - the
addon bakes to a plain mesh and the generator graph can be discarded. So you cannot "regenerate
with lower settings" (radial_n_points / smooth_iterations) after the fact unless the node tree
was kept.

## Fix (works reliably)
1. **Voxel remesh** the dense mesh (`mesh.remesh_voxel_size`, e.g. 0.15 m on a 15 m tree).
   Voxel remesh tolerates non-manifold input - it re-surfaces the *volume* → clean manifold,
   consistent normals. (154k → 53k tris @ 0.15.) Trade-off: twigs thinner than the voxel size
   merge or vanish - **acceptable for low-poly trees whose foliage will be textured cards.**
2. **Now** Decimate-Collapse honors the ratio (manifold input). 53k → exactly 2,800 tris at
   `ratio = 2800/53392`.
3. Re-ground after remesh (voxel can shift the base up a few cm): translate verts so
   `min(v.co.z) == 0` with the object at origin.

## Gotchas
- The **Geometry Nodes leaf modifier keeps evaluating the multi-million-tri scatter** on every
  depsgraph update → repeated MCP "No data received" timeouts. Set the leaf modifier
  `show_viewport = False` / `show_render = False` *before* doing heavy mesh ops, or it chokes
  every subsequent evaluation.
- The real poly budget killer for MTree trees is the **leaf source mesh** (594 tris per leaf
  here), not the instance count (~1058 leaves is reasonable). Converting leaves to 2-tri
  textured cards is what brings the tree into a game budget (1058×2 ≈ 2.1k vs 628k).
- Decimate "flooring" at a value far above your ratio target is a reliable **tell that the mesh
  is non-manifold** - reach for Voxel remesh rather than fighting the ratio.

## Applies to
Any imported/generated organic mesh that won't decimate (scanned meshes, boolean unions,
sapling/tree generators, sculpts with non-manifold edges). Voxel-remesh → Collapse is the
general escape hatch.
